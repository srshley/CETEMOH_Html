01

Le problème de l'état

HTTP est un protocole sans état (stateless) : chaque requête part de zéro. Quand un visiteur affiche page2.php, le serveur n'a absolument aucune mémoire de page1.php — pas de nom, pas de panier, pas de connexion. Chaque page semble se comporter comme si elle recevait un inconnu.

C'est un vrai problème pour tout site réel : « rester connecté », « conserver le panier », « se souvenir des préférences ». PHP y répond avec deux mécanismes de mémoire : les cookies (côté client) et les sessions (côté serveur).

👥
Analogie : des visiteurs amnésiques

Chez un serveur PHP, chaque demande vient d'un visiteur amnésique : il arrive, pose une question, et oublie tout en repartant. Le cookie est le badge qu'on lui laisse en poche (il le rapporte à la visite suivante). La session est un casier numéroté au vestiaire : le visiteur garde la clef, le serveur garde les affaires.

Dans la suite de la séance, nous allons ouvrir ce casier et ce badge : d'abord les cookies (simples, visibles, limités), puis les sessions (côté serveur, plus sûres et plus vastes).

02

Les cookies

Un cookie est un petit texte envoyé au navigateur avec setcookie("nom", valeur, expiration, '/'). À chaque visite suivante, le navigateur le renvoie automatiquement et PHP le place dans la superglobale $_COOKIE.

PHP — setcookie + $_COOKIE 
<?php
  if ($_SERVER["REQUEST_METHOD"] === "POST") {
    setcookie("theme", $_POST["theme"], time() + 3600, "/");
  }

  $theme = $_COOKIE["theme"] ?? "clair";
  echo "Thème actuel : $theme";
?>
RENDU

Thème actuel : sombre

(à la 2e visite après avoir choisi « sombre »)

⚠️
Un cookie remis… mais pas tout de suite

setcookie ajoute un en-tête HTTP : il doit être appelé avant tout affichage (echo, HTML, espace avant <?php…). Surtout : un cookie créé n'apparaît dans $_COOKIE qu'au rechargement suivant, car c'est le navigateur qui le renvoie — au premier affichage, il n'a pas encore été retourné.

Les paramètres de setcookie

ParamètreRôleExemple
nameClé du cookie (obligatoire)"theme"
valueValeur renvoyée par le client"sombre"
expiresTimestamp de péremption (0 = jusqu'à la fermeture du navigateur)time() + 3600
pathPortée du cookie sur le site"/" (tout le site)
domainDomaine couvert"monsite.fr"
secureN'envoie le cookie qu'en HTTPStrue
httponlyInterdit au JavaScript (anti-XSS)true
📝
Supprimer = péremption passée

Un cookie se supprime en le réécrivant avec une expiration dans le passé : setcookie("theme", "", time() - 3600, "/"). Le navigateur l'abandonne de lui-même.

⚡ EXO FLASH La langue qui n'arrive qu'après
  1. Créez langue.php : si $_GET["lang"] est présent, appelez setcookie("lang", $_GET["lang"], time() + 3600, "/") avant le moindre echo.
  2. Affichez ensuite $_COOKIE["lang"] ?? "aucun cookie" avec htmlspecialchars.
  3. Prévoyez ce qu'affiche langue.php?lang=en au tout premier appel, puis vérifiez en rechargant la page : la valeur n'apparaît qu'au chargement suivant. Finissez en réécrivant le cookie avec time() - 3600 pour le supprimer.
Voir un début de correction 
<?php
  if (isset($_GET["lang"])) {
    setcookie("lang", $_GET["lang"], time() + 3600, "/");
  }

  echo "Langue : " . htmlspecialchars($_COOKIE["lang"] ?? "aucun cookie");
?>
03

Les sessions

Une session stocke les données côté serveur (dans des fichiers sur le disque). Le navigateur ne reçoit qu'un identifiant — le session ID — placé dans un cookie PHPSESSID : c'est la clef du casier. Tant que session_start() s'exécute en haut de chaque page, $_SESSION continue à contenir les données de ce visiteur, d'une page à l'autre.

PHP — login.php 
<?php
  session_start();

  if ($_SERVER["REQUEST_METHOD"] === "POST") {
    $user = $_POST["user"] ?? "";
    if ($user !== "") {
      $_SESSION["user"] = $user;   // stocke le visiteur
    }
  }

  if (isset($_SESSION["user"])) {
    echo "Connecté en tant que " . $_SESSION["user"] . "<br>";
    echo "ID de session : " . session_id();
  }
?>
RENDU

Connecté en tant que Alice
ID de session : pq4v2tnhd35sk7q1m6r8fge9c2

PHP — n'importe quelle page 
<?php
  session_start();

  if (isset($_SESSION["user"])) {
    echo "Bonjour " . $_SESSION["user"];
  } else {
    echo "Invité.";
  }
?>
RENDU

Bonjour Alice

📝
session_start() avant tout affichage

Comme setcookie, session_start() envoie des en-têtes. Appelez-le tout en haut du fichier, avant tout echo ou balise HTML, sinon vous obtenez l'erreur « headers already sent » et la session ne démarre pas.

⚡ EXO FLASH Deux pages, un seul casier
  1. Créez ecris.php : session_start(); dès la première ligne, puis stockez $_SESSION["couleur"] = "verte"; et affichez session_id().
  2. Créez lit.php avec le même session_start() en haut, qui affiche $_SESSION["couleur"] ?? "rien en mémoire".
  3. Prévoyez ce que rend lit.php juste après ecris.php, puis vérifiez ; retirez alors session_start() de lit.php : la page retombe sur « rien en mémoire », sans aucun message d'erreur — le piège est justement son silence.
Voir un début de correction 
<?php
  session_start();
  $_SESSION["couleur"] = "verte";

  echo "Enregistré : " . $_SESSION["couleur"] . "<br>";
  echo "Clefs du casier : " . implode(", ", array_keys($_SESSION));
?>
04

Exemple pratique : panier d'achat

Le cas d'école des sessions : un e-commerce doit retenir les articles choisis pendant toute la navigation. Le panier est un tableau stocké dans $_SESSION, accessible sur chaque page, qui évolue au fil des clics.

PHP — panier.php 
<?php
  session_start();
  $_SESSION["panier"] = $_SESSION["panier"] ?? [];

  if (isset($_GET["ajouter"])) {
    $article = $_GET["ajouter"];
    if (!in_array($article, $_SESSION["panier"])) {
      $_SESSION["panier"][] = $article;
    }
  }

  if (isset($_GET["vider"])) {
    $_SESSION["panier"] = [];
  }

  if (empty($_SESSION["panier"])) {
    echo "Panier vide.";
  } else {
    foreach ($_SESSION["panier"] as $article) {
      echo "· $article<br>";
    }
    echo "Total : " . count($_SESSION["panier"]) . " article(s)";
  }
?>
RENDU

· Clavier mécanique
· Écran 27"
Total : 2 article(s)

💡
Initialiser avant d'écrire

Toujours initialiser le panier avant d'y écrire : $_SESSION["panier"] = $_SESSION["panier"] ?? [];. Un nouveau visiteur arrive sans aucune donnée stockée : lire $_SESSION["panier"] avant de le créer déclencherait une erreur undefined index.

05

Déconnexion

Se déconnecter, c'est refermer le casier et jeter la clef. Deux fonctions de base : session_unset() vide $_SESSION de toutes ses données, session_destroy() détruit la session côté serveur (données et clef). On efface en plus le cookie de session côté navigateur.

PHP — logout.php 
<?php
  session_start();

  session_unset();          // vide $_SESSION
  session_destroy();        // détruit la session côté serveur

  // Supprime le cookie de session
  setcookie("PHPSESSID", "", time() - 3600, "/");

  echo "Vous êtes déconnecté.";
?>
RENDU

Vous êtes déconnecté.

📝
session_destroy() seul ne suffit pas

session_destroy() agit uniquement côté serveur. Aussi : $_SESSION n'est vidé qu'au prochain chargement. Pour vider immédiatement les données visibles, appelez session_unset() avant — ou réassignez $_SESSION = [].

06

Sessions vs Cookies

Les deux outils répondent au même besoin de mémoire, mais ont des forces opposées. Retenez l'essentiel : le cookie est une donnée client (lisible, modifiable, envoyée en continu), la session est une donnée serveur protégée derrière un simple identifiant.

CritèreCookieSession
Stockagenavigateur (client)serveur (fichiers)
Duréede quelques secondes à plus d'un an, programméejusqu'à la fermeture du navigateur, ou délai d'inactivité serveur
Taille max≈ 4 Ko par cookielimitée par le disque du serveur
Sécuritélisible / modifiable par le client et le JSdonnées jamais transmises (ID seul voyage)
Cas d'usage typiquespréférences claires et non sensibles : thème, langueconnexion, panier, données sensibles
💡
Règles de sécurité des cookies

Toujours httponly = true pour empêcher le JavaScript de lire le cookie, et secure = true quand le site est en HTTPS : le cookie ne circule plus jamais en texte clair. Et ne stockez jamais de mot de passe — pas même encodé — dans un cookie.

Sur la durée, il y a une nuance que l'on rate souvent : le cookie PHPSESSID est créé sans date d'expiration, donc le navigateur l'efface quand il est totalement fermé — refermer un onglet ne suffit pas, et la session redevient vierge à la réouverture. Le serveur, lui, supprime les fichiers de session abandonnés au bout de session.gc_maxlifetime (1 440 secondes, soit 24 minutes, par défaut) : un visiteur inactif plus de 24 minutes est déconnecté sans prévenir. Règle pratique : une donnée qui doit survivre à la fermeture du navigateur (« se souvenir de moi ») ne se met pas dans $_SESSION mais dans un cookie persistant — avec expires daté, httponly et secure.

07

Exercices pratiques

EX 01 🌗 Thème mémorisé
  1. Créez exo_theme.php avec un formulaire POST proposant "clair" / "sombre".
  2. Au POST, stockez le choix dans un cookie d'un an, path "/".
  3. Affichez le thème actuel depuis $_COOKIE (valeur par défaut : "clair") et testez en rechargeant.

Indice : time() + 365 * 24 * 3600 vaut un an ; le cookie ne se relit qu'au chargement suivant.

EX 02 🔐 Mini-connexion
  1. Créez exo_login.php : un formulaire POST (pseudo + mot de passe).
  2. Si le couple vaut "alice" / "azerty", stockez le pseudo dans $_SESSION["user"].
  3. Sur toute requête où $_SESSION["user"] existe déjà, affichez « Bienvenue {pseudo} » ; sinon, affichez le formulaire.

Indice : session_start() tout en haut du fichier, avant le moindre echo ou HTML.

EX 03 🗄️ Compteur de visites
  1. Créez exo_visites.php : à chaque rechargement, incrémentez $_SESSION["visites"] (défaut : 1).
  2. Affichez « Vous avez visité cette page N fois ».
  3. Ajoutez un bouton « Remise à zéro » (GET) qui remet le compteur à 0.

Indice : à chaque chargement, $_SESSION["visites"] = ($_SESSION["visites"] ?? 0) + 1; suffit.

EX 04 🛒 Panier complet
  1. Reprenez le panier de la séance : ajoutez des articles via des liens ?ajouter=....
  2. Ajoutez la suppression d'un article précis via ?retirer=... (recherchez son index avec array_search, puis unset).
  3. Ajoutez un lien ?vider=1 qui vide le panier, et affichez toujours son contenu + son total.

Indice : array_search peut retourner false : testez !== false avant d'appeler unset.

08

Bilan & mini-glossaire

Ce que vous maîtrisez

  • Pourquoi HTTP est stateless et ce que ça implique
  • Créer / supprimer un cookie avec setcookie, puis le relire via $_COOKIE
  • Les paramètres clés : path, secure, httponly
  • session_start() systématiquement en haut de page
  • Écrire, relire et modifier un tableau $_SESSION
  • Construire un panier (ajouter, retirer, vider)
  • Se déconnecter avec session_unset + session_destroy (+ effacer le cookie)
🚨
Erreurs fréquentes
  • Oublier session_start() → $_SESSION est vide sans warning clair.
  • Appeler setcookie ou session_start après un affichage → « headers already sent ».
  • Attendre la valeur du cookie tout de suite après setcookie → elle n'arrive qu'au chargement suivant.
  • Stocker un mot de passe (même encodé) dans un cookie lisible par le client.
  • Utiliser session_destroy() seul et croire que $_SESSION est vidée sur-le-champ.

Mini-glossaire

Stateless
Protocole sans mémoire entre deux requêtes, comme HTTP.
Cookie
Petite donnée stockée chez le client, renvoyée à chaque requête.
setcookie
Envoie l'en-tête Set-Cookie ; à appeler avant tout affichage.
$_COOKIE
La superglobale qui contient les cookies renvoyés par le navigateur.
Session
Données stockées côté serveur, identifiées par un session ID.
session_id
Identifiant unique de la session, transporté par le cookie PHPSESSID.
session_unset
Vide le contenu de $_SESSION.
session_destroy
Détruit la session côté serveur (effet différé dans $_SESSION).
