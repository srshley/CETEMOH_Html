01

Une base de données, c'est quoi ?

Une base de données est un système structuré et persistant : les données survivent à la fin du script (a contrario des variables), et elles sont organisées pour être retrouvées vite, même à des millions de lignes. L'objet central est la table : un tableau fictif avec des colonnes fixes (les champs) et autant de lignes (les enregistrements) qu'il y a de données.

SQL — la table « eleves » 
table : eleves
+----+--------+---------+-------+
| id | nom    | prenom  | note  |
+----+--------+---------+-------+
| 1  | Martin | Alice   | 15    |
| 2  | Dupont | Karim   | 12    |
| 3  | Verne  | Sofiane | 18    |
+----+--------+---------+-------+
RENDU

4 colonnes, 3 lignes.
Chaque ligne est un élève,
retrouvé par son id.

🗂️
Analogie : le classeur Excel

Une base de données ressemble à un classeur Excel géant et ultra-organisé : le classeur contient des feuilles (tables), chaque feuille a des colonnes (champs) et des lignes (enregistrements). La grande différence : on interroge le classeur en langage SQL (« donne-moi les élèves avec une note > 10 »), et les accès simultanés sont gérés pour vous.

Avec XAMPP, le serveur MySQL se lance depuis le panneau de contrôle, et l'outil phpMyAdmin (http://localhost/phpmyadmin) permet de créer les bases, les tables et de les examiner à la main. C'est là que nous créerons la base ecole et la table eleves utilisées dans toute la séance.

02

Se connecter avec PDO

PDO (PHP Data Objects) est l'interface standard de PHP pour parler aux bases de données. On crée un objet de connexion en passant un DSN (Data Source Name) qui décrit où se trouve la base, plus l'utilisateur et le mot de passe. Avec XAMPP, l'utilisateur par défaut est root sans mot de passe.

PHP — connexion PDO 
<?php
  try {
    $pdo = new PDO(
      "mysql:host=localhost;dbname=ecole;charset=utf8mb4",
      "root",          // utilisateur
      "",              // mot de passe (vide sous XAMPP)
      [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]
    );
    echo "Connexion réussie.";
  } catch (PDOException $e) {
    echo "Erreur de connexion : " . $e->getMessage();
  }
?>
RENDU

Connexion réussie.

Anatomie du DSN

MorceauRôleExemple
mysql:host=...Le type de base et l'adresse du serveurmysql:host=localhost
dbname=...La base choisiedbname=ecole
charset=...L'encodage (les accents !)charset=utf8mb4
2e argumentNom d'utilisateur MySQL"root"
3e argumentMot de passe MySQL"" (XAMPP)
📝
L'option ERRMODE_EXCEPTION

Passée en 4e argument, PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION fait lever une exception en cas d'erreur SQL (PDOException) — au lieu de rester silencieux. Vos try/catch (section 06) deviennent efficaces partout.

Le compte root sans mot de passe est un confort de XAMPP : sur un vrai serveur, créez un utilisateur MySQL dédié auquel vous accordez l'accès à une seule base (GRANT SELECT, INSERT ON ecole.* TO 'web'@'localhost') — un script compromis ne pourra alors rien toucher d'autre. Évitez aussi de rouvrir une connexion à chaque page : construisez $pdo une seule fois dans connexion.php et rechargez-le partout avec require, pour centraliser le coût de connexion et les identifiants.

03

Requêtes préparées

Une requête préparée envoie le squelette SQL à la base avec des emplacements :param (placeholders), puis les valeurs séparément. La base sait ainsi ce qui est code et ce qui est donnée : aucune valeur ne peut détourner la requête.

PHP — SELECT préparé 
<?php
  $seuil = $_GET["seuil"] ?? 10;

  $stmt = $pdo->prepare(
    "SELECT * FROM eleves WHERE note > :seuil ORDER BY nom");
  $stmt->bindValue(":seuil", $seuil, PDO::PARAM_INT);
  $stmt->execute();

  foreach ($stmt as $ligne) {
    echo $ligne["nom"] . " " . $ligne["note"] . "<br>";
  }
?>
RENDU

Martin 15
Verne 18

(si seuil = 10)

🚨
JAMAIS de variables concaténées dans le SQL

Écrivez jamais "SELECT * FROM eleves WHERE id = $id" : un internaute qui met id=1 OR 1=1 dans l'URL récupère toute la table — c'est l'injection SQL, faille #1 des sites PHP. Les requêtes préparées rendent cette attaque impossible : la valeur reste une valeur, elle ne réécrit jamais la requête.

⚡ EXO FLASH Le seuil qui n'avale pas la table
  1. Créez flash_seuil.php : réutilisez la connexion $pdo du cours et préparez SELECT nom, note FROM eleves WHERE note > :seuil.
  2. Liez $_GET["seuil"] ?? 10 avec bindValue(":seuil", ..., PDO::PARAM_INT), exécutez et affichez chaque ligne.
  3. Prévoyez le résultat de ?seuil=1%20OR%201=1 puis vérifiez : avec PARAM_INT, la valeur devient l'entier 1 — le squelette SQL, lui, n'a pas bougé d'un caractère.
Voir un début de correction 
<?php
  $seuil = $_GET["seuil"] ?? 10;
  $stmt = $pdo->prepare("SELECT nom, note FROM eleves WHERE note > :seuil");
  $stmt->bindValue(":seuil", $seuil, PDO::PARAM_INT);
  $stmt->execute();
  foreach ($stmt as $l) {
    echo $l["nom"] . " — " . $l["note"] . "<br>";
  }
?>
04

Lire les résultats

Après execute(), le statement contient les lignes renvoyées. On les récupère avec fetch() (une ligne à la fois) ou fetchAll() (tout d'un coup). Le mode décide la forme : tableau associatif (FETCH_ASSOC) ou objet (FETCH_OBJ).

MéthodeCe qu'elle renvoie
fetch()une ligne (null si plus rien) — idéal pour un seul résultat
fetchAll()toutes les lignes dans un tableau
fetchColumn()la 1re colonne de la 1re ligne — idéal pour un COUNT
rowCount()le nombre de lignes touchées (SELECT, INSERT, UPDATE…)
FETCH_ASSOCmode : tableau associatif $ligne["nom"]
FETCH_OBJmode : objet anonyme $ligne->nom
PHP — fetchAll + FETCH_ASSOC 
<?php
  $stmt = $pdo->query(
    "SELECT nom, note FROM eleves WHERE note >= 15");
  $lignes = $stmt->fetchAll(PDO::FETCH_ASSOC);

  echo "Élèves brillants :<br>";
  foreach ($lignes as $e) {
    echo "· " . $e["nom"] . " (" . $e["note"] . "/20)<br>";
  }
?>
RENDU

Élèves brillants :
· Martin (15/20)
· Verne (18/20)

05

Écrire des données

Trois verbes SQL modifient la table : INSERT (ajouter), UPDATE (modifier), DELETE (supprimer). Les requêtes préparées sont obligatoires dès qu'une valeur vient du visiteur — et gardez en tête qu'un UPDATE sans WHERE modifie toutes les lignes, sans exception.

PHP — INSERT / UPDATE / DELETE 
<?php
  // INSERT : ajouter un élève
  $stmt = $pdo->prepare(
    "INSERT INTO eleves (nom, prenom, note)
     VALUES (:nom, :prenom, :note)");
  $stmt->execute([
    ":nom" => "Bernard", ":prenom" => "Léo", ":note" => 14
  ]);
  echo "Ajouté avec l'id " . $pdo->lastInsertId() . "<br>";

  // UPDATE : remonter la note de Léo
  $stmt = $pdo->prepare(
    "UPDATE eleves SET note = :note WHERE nom = :nom");
  $stmt->execute([":note" => 16, ":nom" => "Bernard"]);

  // DELETE : le retirer
  $stmt = $pdo->prepare(
    "DELETE FROM eleves WHERE nom = :nom");
  $stmt->execute([":nom" => "Bernard"]);
?>
RENDU

Ajouté avec l'id 4

⚠️
Le WHERE qui manque

"UPDATE eleves SET note = 20" sans WHERE met 20 à tous les élèves. Idem pour un DELETE FROM sans condition : tout s'envole. Avant d'exécuter, relisez la clause WHERE ; et pour afficher « modification enregistrée », fiez-vous à $stmt->rowCount() : il renvoie le nombre de lignes touchées par le dernier INSERT / UPDATE / DELETE.

⚡ EXO FLASH Insérer, mettre à jour, mesurer
  1. Créez flash_ecrire.php : un INSERT vers eleves (nom, prénom, note) avec un seul execute([...]) — sans bindValue.
  2. Affichez $pdo->lastInsertId(), puis passez la note de cet élève à 18 via un UPDATE ... WHERE id = :id préparé et affichez $stmt->rowCount().
  3. Prévoyez ce qu'affichera un second UPDATE identique (note déjà à 18), puis vérifiez : MySQL ne compte que les lignes réellement changées.
Voir un début de correction 
<?php
  $ins = $pdo->prepare("INSERT INTO eleves (nom, prenom, note) VALUES (:n, :p, :note)");
  $ins->execute([":n" => "Pastor", ":p" => "Julie", ":note" => 17]);
  $id = $pdo->lastInsertId();
  $up = $pdo->prepare("UPDATE eleves SET note = :note WHERE id = :id");
  $up->execute([":note" => 18, ":id" => $id]);
  echo "id " . $id . ", lignes modifiées : " . $up->rowCount();
?>
06

Gérer les erreurs & transactions

Avec ERRMODE_EXCEPTION, toute erreur SQL lève une PDOException : c'est à vous de la catcher pour donner un message utile sans exposer les détails techniques (connexion, structure de la base…). Ensuite, les transactions garantissent l'atomicité : soit toutes les requêtes du bloc aboutissent, soit aucune ne s'applique.

PHP — transaction 
<?php
  try {
    $pdo->beginTransaction();

    // Virement interne : les deux UPDATE font un tout
    $pdo->prepare(
      "UPDATE comptes SET solde = solde - 100 WHERE id = 1"
    )->execute();
    $pdo->prepare(
      "UPDATE comptes SET solde = solde + 100 WHERE id = 2"
    )->execute();
    $pdo->commit();     // applique TOUT
    echo "Transfert effectué.";
  } catch (PDOException $e) {
    $pdo->rollBack();   // annule TOUT
    echo "Erreur : transfert annulé.";
  }
?>
RENDU

Transfert effectué.

(ou « Erreur : transfert annulé. » si un UPDATE échoue)

📝
Pourquoi un rollback ?

Si le premier UPDATE réussit et le second échoue, l'argent serait parti sans arriver : données corrompues. La transaction « arme » la base — rien n'est réellement écrit tant que commit() n'est pas appelé. En cas d'erreur, rollBack() efface tout le chemin déjà parcouru.

07

Exercices pratiques

EX 01 🔌 Connexion blindée
  1. Créez connexion.php : new PDO vers une base ecole, avec charset=utf8mb4 et ERRMODE_EXCEPTION.
  2. Entourez le tout d'un try/catch qui affiche « Base indisponible » en cas d'échec.
  3. Testez avec une mauvaise base (dbname=fausse) : le message doit apparaître.

Indice : le DSN complet est fourni dans la séance — seul le nom de la base change.

EX 02 📋 Liste préparée
  1. Dans un formulaire GET avec un champ seuil, préparez un SELECT * FROM eleves WHERE note >= :seuil.
  2. Affichez chaque élève trouvé sous la forme nom prenom — note/20.
  3. Comptez-les avec rowCount() et affichez « N élèves ».

Indice : passez le seuil via execute([":seuil" => ...]), jamais par concaténation.

EX 03 ➕ Ajout d'élève
  1. Créez un formulaire POST (nom, prénom, note) qui INSERT via une requête préparée.
  2. Affichez l'identifiant créé avec $pdo->lastInsertId().
  3. Ajoutez la gestion d'erreur : message approprié si l'insertion échoue, et confirmation si rowCount() vaut 1.

Indice : le même try/catch englobe l'exécution et la confirmation.

EX 04 🏦 Transaction
  1. Créez une table comptes (id, solde) avec quelques lignes via phpMyAdmin.
  2. Reprenez le code de virement de la séance : les deux UPDATE doivent se faire dans une transaction.
  3. Simulez une panne (écrivez sur une colonne inexistante) pour vérifier que rollBack() remet les soldes d'origine.

Indice : placez toutes les requêtes entre beginTransaction() et commit() / rollBack() — pas une de plus.

08

Bilan & mini-glossaire

Ce que vous maîtrisez

  • Tables, colonnes, lignes : le vocabulaire des bases de données
  • MySQL + phpMyAdmin sous XAMPP
  • Se connecter avec new PDO(dsn, user, pass) et un DSN host/dbname/charset, en try/catch
  • Préparer et exécuter : prepare, bindValue, execute
  • Lire avec fetch, fetchAll, rowCount et les modes FETCH_*
  • Écrire avec INSERT / UPDATE / DELETE et observer rowCount
  • Protéger un bloc d'opérations : beginTransaction / commit / rollback
🚨
Erreurs fréquentes
  • Concaténer une variable dans le SQL → injection SQL, table entière exposée.
  • Oublier le WHERE dans un UPDATE ou DELETE → toute la table modifiée ou vidée.
  • Mauvais nom de base dans le DSN, ou charset absent → accents cassés.
  • Ne pas catcher la PDOException → page cassée et détails techniques visibles.
  • Confondre fetch (une ligne) et fetchAll (toutes) puis itérer sur la mauvaise variable.

Mini-glossaire
