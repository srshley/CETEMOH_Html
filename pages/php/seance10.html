01

Lire un fichier

PHP peut lire des fichiers présents sur le serveur : un journal d'erreurs, un fichier de configuration, des données exportées en CSV. La méthode la plus simple est file_get_contents("fichier.txt"), qui renvoie tout le contenu en une seule chaîne. Si le fichier n'existe pas, elle renvoie false (et un avertissement).

Pour un traitement ligne par ligne (utile pour de gros fichiers), on ouvre le fichier avec fopen, on le parcourt avec fgets puis on le ferme avec fclose.

PHP — file_get_contents 
<?php
  $contenu = file_get_contents("notes.txt");

  if ($contenu === false) {
    echo "Fichier introuvable.";
  } else {
    echo $contenu;
  }
?>

📓
Analogie : le cahier

Un fichier est un cahier : fopen l'ouvre, fgets lit une page (une ligne), fwrite écrit au stylo, et fclose referme le cahier. Ouvrir sans fermer, c'est laisser un livre traîner ouvert : le serveur garde des ressources mobilisées pour rien.

⚡ EXO FLASH Le fichier introuvable
  1. Créez devoirs.txt avec trois lignes de texte, puis lire_devoirs.php qui affiche tout le contenu avec file_get_contents.
  2. Comptez les retours à la ligne avec substr_count($contenu, "\n") et affichez le résultat sous le texte.
  3. Prévoyez ce que rend le script si vous renommez le fichier en devoirs1.txt, puis vérifiez : sans test, un avertissement « Failed to open stream » s'affiche sur la page ; avec $contenu === false, c'est votre message « Fichier introuvable. » qui prend la main.
Voir un début de correction 
<?php
  $contenu = file_get_contents("devoirs.txt");

  if ($contenu === false) {
    echo "Fichier introuvable.";
  } else {
    echo $contenu . "<br>Lignes : " . substr_count($contenu, "\n");
  }
?>
02

Écrire dans un fichier

L'inverse de la lecture : file_put_contents("fichier.txt", $texte) écrit une chaîne dans un fichier. Sans troisième argument, il écrase le contenu existant. Avec le flag FILE_APPEND, il ajoute à la fin — parfait pour un journal (log).

PHP — file_put_contents + fwrite 
<?php
  // Écrase tout le contenu
  file_put_contents("notes.txt", "Nouvelle liste\n");

  // Ajoute à la fin
  file_put_contents("notes.txt", "- Acheter du pain\n", FILE_APPEND);

  // Version fopen : ouvrir en mode "a" (append)
  $fp = fopen("notes.txt", "a");
  fwrite($fp, "- Filmer le TP\n");
  fclose($fp);

  echo file_get_contents("notes.txt");
?>
RENDU

Nouvelle liste
- Acheter du pain
- Filmer le TP

📝
w écrase, a ajoute

C'est la règle d'or des modes d'écriture : w est le taille-zéro (il vide le fichier à l'ouverture), a est le post-it collé à la fin (il ajoute sans toucher à l'existant). Avec file_put_contents, l'équivalent de a est le flag FILE_APPEND ; celui de w, c'est ne rien passer du tout.

03

Les modes d'ouverture

Le second argument de fopen décide comment on accède au fichier : lecture seule, écriture, ajout, ou les deux à la fois. Choisir le mauvais mode est une source classique de perte de données.

ModeSignificationSi le fichier existeSi le fichier est absent
rLecture seule, curseur au débutgardé intacterreur (false)
r+Lecture + écrituregardé intacterreur (false)
wÉcriture seulevidé (écrasé)créé
w+Écriture + lecturevidé (écrasé)créé
aÉcriture à la fin (append)gardé intactcréé
a+Ajout + lecturegardé intactcréé
xCréation exclusiveerreur si déjà présentcréé
⚠️
Attention au mode w

Dès que fopen("rapport.txt", "w") s'exécute, le fichier est déjà vidé — même si vous n'écrivez jamais rien après. Ouvrir par réflexe en w peut détruire un fichier de données en une ligne. Pour lire : r. Pour ajouter : a.

Deux nuances que les tableaux ne montrent pas. D'abord, les modes avec + ne placent pas le curseur à la fin : en r+, le fichier est gardé intact mais le curseur démarre au premier octet, donc fwrite($fp, "bon") sur « PHP est nulle » donne « bon est nulle » — pour ajouter du texte avec +, déplacez d'abord le curseur avec fseek($fp, 0, SEEK_END). Ensuite, testez systématiquement le retour de fopen avec if ($fp === false) : en PHP 8, passer ce false à fwrite ou fgets provoque une TypeError qui interrompt la page. Le mode x est le seul qui refuse d'écrire si le fichier existe déjà : c'est le choix à retenir quand vous devez créer sans jamais écraser.

04

Fonctions de fichiers

Au-delà de lire et écrire, PHP fournit une boîte à outils complète : interroger un fichier, le déplacer, le supprimer, lister un dossier. Voici les fonctions à connaître.

FonctionRôleExemple
file_exists($f)Teste si le fichier existefile_exists("notes.txt")
filesize($f)Taille en octetsfilesize("notes.txt") → 34
filemtime($f)Date de dernière modification (timestamp)date("d/m/Y", filemtime("notes.txt"))
unlink($f)Supprime le fichierunlink("old.txt")
rename($a, $b)Renomme ou déplacerename("a.txt", "dossiers/b.txt")
copy($a, $b)Copie le fichiercopy("notes.txt", "sauvegarde.txt")
scandir($dir)Liste les entrées d'un dossierscandir("uploads")
mkdir($dir)Crée un dossiermkdir("logs")
💡
Les points de scandir

scandir renvoie toujours . (dossier courant) et .. (dossier parent) — filtrez-les avec $entree !== "." && $entree !== "..". Et stockez toujours les uploads dans un dossier dédié (uploads/), hors des scripts exécutés.

⚡ EXO FLASH Inventaire du dossier
  1. Créez inventaire.php : parcourez scandir(".") avec foreach et filtrez . et ...
  2. Affichez pour chaque entrée restante son nom, sa taille avec filesize et sa date de modification avec date("d/m/Y", filemtime(…)) — un sous-dossier s'y glisse : remarquez la taille qu'il renvoie.
  3. Prévoyez ce que renvoie unlink("vieux.txt") quand ce fichier n'existe pas, puis vérifiez : false et un avertissement — d'où le réflexe de tester file_exists avant de supprimer.
Voir un début de correction 
<?php
  foreach (scandir(".") as $entree) {
    if ($entree === "." || $entree === "..") continue;
    echo "$entree : " . filesize($entree) . " octets, modifié le "
       . date("d/m/Y", filemtime($entree)) . "<br>";
  }
?>
05

Upload de fichiers

Un formulaire peut envoyer un fichier avec l'attribut enctype="multipart/form-data" (obligatoire, et uniquement avec la méthode POST). PHP réceptionne le fichier dans la superglobale $_FILES. Le fichier est d'abord posé temporairement sur le serveur : c'est à vous de le déplacer vers sa destination finale.

HTML — Formulaire d'upload 
<form method="post" action="upload.php"
      enctype="multipart/form-data">
  <input type="file" name="photo">
  <button type="submit">Envoyer</button>
</form>
RENDU

Aucun fichier choisi

PHP — upload.php 
<?php
  if ($_SERVER["REQUEST_METHOD"] === "POST") {

    if ($_FILES["photo"]["error"] === UPLOAD_ERR_OK) {
      echo "Nom reçu : " . $_FILES["photo"]["name"] . "<br>";
      echo "Taille : " . $_FILES["photo"]["size"] . " octets";
    } else {
      echo "Échec de l'upload.";
    }
  }
?>
RENDU

Nom reçu : ma_photo.jpg
Taille : 24580 octets

Chaque entrée de $_FILES est un tableau associatif à cinq clés :

CléContenuExemple
nameNom original chez le client (fiable = non)ma_photo.jpg
typeType MIME déclaré par le navigateurimage/jpeg
tmp_nameChemin du fichier temporaire sur le serveur/tmp/phpA1b2
errorCode erreur (0 = UPLOAD_ERR_OK)0, 1, 2…
sizeTaille réelle en octets24580
📝
Le fichier temporaire disparaît

PHP détruit automatiquement le fichier de tmp_name à la fin du script. Si vous ne le déplacez pas avec move_uploaded_file pendant la requête, il est perdu. C'est pourquoi une vérification oubliée ne se « corrige » pas après coup.

06

Sécuriser les uploads

Accepter un fichier, c'est accepter un code potentiellement dangereux sur votre serveur : un .php déguisé en image, une image de 2 Go qui sature le disque, un nom de fichier qui écrase un fichier existant. Comme $_FILES["name"] et $_FILES["type"] sont déclarés par le client, on ne les utilise jamais seuls.

PHP — Upload sécurisé 
<?php
  $extensions = ["jpg", "jpeg", "png", "gif"];
  $max = 2 * 1024 * 1024;   // 2 Mo

  $ext = strtolower(pathinfo(
    $_FILES["photo"]["name"], PATHINFO_EXTENSION));

  if ($_FILES["photo"]["error"] !== UPLOAD_ERR_OK) {
    echo "Erreur d'upload.";
  } elseif (!in_array($ext, $extensions)) {
    echo "Extension interdite ($ext).";
  } elseif ($_FILES["photo"]["size"] > $max) {
    echo "Fichier trop lourd (max 2 Mo).";
  } else {
    $nouveau = "uploads/" . uniqid() . "." . $ext;
    move_uploaded_file($_FILES["photo"]["tmp_name"], $nouveau);
    echo "Fichier enregistré : $nouveau";
  }
?>
RENDU

Fichier enregistré : uploads/638d2f1c9a4b7.jpg

🚨
Les 4 règles de survie
  • Ne jamais enregistrer directement le fichier dans le dossier web sans vérification.
  • Vérifier l'extension + le type MIME côté serveur (avec finfo), pas le champ type seul.
  • Toujours utiliser move_uploaded_file : elle refuse tout fichier qui ne vient pas d'un upload légitime.
  • Régénérer le nom (uniqid) : jamais le nom envoyé par le client, qui peut contenir des ../ ou écraser un fichier.
💡
Un dossier dédié

Stockez les uploads dans un dossier spécifique (uploads/) en dehors des scripts exécutables, et refusez les extensions dangereuses (php, phtml, php5…) même si la liste blanche ne les contient pas — défense en profondeur.

07

Exercices pratiques

EX 01 📖 Journal de bord
  1. Créez exo_journal.php, écrivez « Premier contact » dans journal.txt avec file_put_contents.
  2. Ajoutez ensuite une ligne datée avec FILE_APPEND puis date("d/m H:i").
  3. Relisez le fichier et affichez son contenu, puis sa taille avec filesize.

Indice : appelez file_put_contents deux fois — sans puis avec le flag FILE_APPEND.

EX 02 🔢 Compteur de lignes
  1. Le fichier eleves.txt contient un nom par ligne. Ouvrez-le avec fopen en mode r.
  2. Parcourez-le avec fgets et affichez chaque ligne numérotée.
  3. Comptez les lignes et affichez « N élèves ».

Indice : utilisez un compteur $i incrémenté dans le while, et n'oubliez pas fclose.

EX 03 ♻️ Gestion de fichiers
  1. Créez source.txt, copiez-le en sauvegarde.txt avec copy.
  2. Renommez sauvegarde.txt en archive_2026.txt avec rename.
  3. Supprimez source.txt avec unlink, puis vérifiez au moyen de file_exists et affichez l'état de chacun.

Indice : après chaque étape, un file_exists confirmé par un echo rend l'exercice limpide.

EX 04 📤 Upload blindé
  1. Créez le formulaire d'upload du cours (avec enctype="multipart/form-data").
  2. Ajoutez les 3 contrôles : code d'erreur via $_FILES["f"]["error"], extension dans la liste ["jpg", "png", "pdf"], taille <= 1 Mo.
  3. Si tout est bon, déplacez le fichier dans uploads/ avec un nom régénéré par uniqid().

Indice : ressortez l'extension avec pathinfo(..., PATHINFO_EXTENSION) et normalisez-la via strtolower.

08

Bilan & mini-glossaire

Ce que vous maîtrisez

  • Lire un fichier d'un bloc (file_get_contents) ou ligne par ligne (fgets)
  • Écrire et ajouter du contenu (file_put_contents, fwrite, FILE_APPEND)
  • Choisir le bon mode d'ouverture : r, w, a… et savoir que w écrase
  • Interroger, copier, renommer, supprimer un fichier (file_exists, unlink…)
  • Lister un dossier avec scandir
  • Recevoir un upload via $_FILES et lire ses 5 clés
  • Sécuriser un upload : extension, taille, move_uploaded_file, nom régénéré
  • Fermer chaque fichier ouvert avec fclose
🚨
Erreurs fréquentes
  • Ouvrir en mode w au lieu de r ou a → le fichier d'origine est vidé instantanément.
  • Oublier fclose → descripteurs de fichiers qui s'accumulent sur le serveur.
  • Oublier enctype="multipart/form-data" → $_FILES reste vide, seul le nom du fichier arrive.
  • Faire confiance à $_FILES["type"] ou au nom d'origine → faille de sécurité.
  • Copier file_get_contents("inexistant.txt") dans une page sans tester file_exists → avertissement à l'écran.

Mini-glossaire

fopen / fclose
Ouverture / fermeture d'un fichier, avec un mode d'accès.
fgets
Lit une ligne du fichier ouvert, avance le curseur.
fwrite
Écrit une chaîne dans le fichier ouvert.
FILE_APPEND
Flag de file_put_contents ajoutant à la fin au lieu d'écraser.
Mode d'ouverture
Argument de fopen (r, w, a…) précisant lecture / écriture.
unlink / rename / copy
Suppression / renommage-déplacement / copie d'un fichier.
$_FILES
Superglobale contenant les fichiers reçus via un formulaire d'upload.
move_uploaded_file
Déplace le fichier temporaire vers sa destination finale (contrôle l'origine).
